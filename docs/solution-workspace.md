# ソリューションの複数プロジェクトと、整理した操作画面

## 複数プロジェクト

`.sln` または `.slnx` を一度読み込むと、読み込み済みのC#プロジェクトを同じワークスペースで調査できます。最初の許可フォルダーは、ソリューションと参照プロジェクトを含む親フォルダーを選んでください。許可範囲外の参照先やリンクファイルは、無断で読み込みません。

- クラス検索は「すべてのプロジェクト」と個別プロジェクトを切り替えます。クラスを選んでも検索範囲は勝手に狭まりません。
- ビルド・DLLの対象と検索範囲を区別します。クラスを選択すると所属するプロジェクトのDLLを調査対象とし、同じ名前の別プロジェクトを名前だけで混同しません。同名の場合は短いパスの末尾を添えて表示します。
- 「準備」の「含まれるプロジェクトと参照関係」で、Roslynが評価したProjectReferenceの方向を確認できます。単なるテキスト内の名前の一致ではありません。
- ソースの参照検索は読み込み済みソリューション全体を対象にします。呼び出し元が別プロジェクトでも、索引にあればボタンで移動できます。
- 静的解析は読み込み済みソリューション全体です。選択プロジェクトだけのスキャンではありません。ボタンにも全体解析であることを表示しました。
- ビルドは選んだ1プロジェクトとその依存先です。今回、ソリューション内の独立した全プロジェクトを一括ビルドする新機能は追加していません。
- JIT・プロファイルには起動可能なアプリが必要です。ライブラリを選んだ場合、読み込み済みの参照グラフ上でそのライブラリに到達する実行アプリを候補にし、1つなら選択します。複数あれば選択を求め、無関係のアプリを勝手に選びません。候補一覧からの手動選択も可能です。

参照関係はソースのプロジェクト構成です。実際にどのDLLをロードするかや、対象メソッドが実行されるかまで証明するものではありません。独自ビルド・Unity専用構成・C++プロジェクト・任意のマルチターゲット構成を網羅検証したとはしていません。DLL候補やPDBの同一性については既存の検査と制限を維持します。

`dotnet build` の参照先を含むビルドについての一次資料:
https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-build

## 画面を4つの入口に整理

サイドバーの通常項目は次の4つです。

| 入口 | 目的 |
|---|---|
| ダッシュボード | 解析状況の概要 |
| プロジェクト調査 | 読み込み・コード調査・実行・結果 |
| 確認状況・差分 | チェック済み・最適化済み・変更の確認 |
| エージェントの活動 | 外部エージェントの進行を表示 |

「検出候補」「決定論的解析」「性能ホットスポット」「メソッド解析」「仮説・証拠」「テストと性能」「ビルドと解析の準備」「アセンブリ解析」「プロファイル取得」「調査優先度」は、折りたたんだ **詳細ツール** にまとめました。削除はしていません。従来のURLは有効で、詳細ページを直接開くと対応するメニューを展開します。「使い方・サンプル」は補助リンクとして残します。

プロジェクト調査の中は **準備 / コード調査 / 実行・検証 / 結果** のタブに分け、同時にすべてのフォームを並べないようにしました。選択したクラス、入力済みの引数、取得結果はタブを切り替えても保持します。結果を取得したら結果タブへ、参照先のメソッドを選んだらコード調査へ進みます。タブ移動そのものでモデル・MSBuild・アプリを実行しません。

キーボードではタブ上の左右矢印、Home/Endで画面を切り替えられます。狭い画面では主要メニュー・タブを2列にし、ページ全体の横スクロールを避けています。

## サンプルで複数プロジェクトを試す

既存のGameLab本体・テスト・ベンチマークをまとめたファイルを追加しました。

`samples/Tenka.Sample.GameLab/Tenka.Sample.GameLab.slnx`

「準備」でこのソリューションを参照・読み込みすると、3プロジェクトをまとめて扱えます。単体サンプル選択ボタンは従来どおり本体の.csprojを選びます。初回にテスト/ベンチマークの依存関係が不足している場合は復元が必要です。静的解析を行うだけでテストが実行されたことにはなりません。

## 更新と検証

起動中の甜花ちゃんとMCPアダプターを終了し、`git pull --ff-only`、`start.bat` の順で更新します。C#にもプロジェクト参照情報の追加があるため、ブラウザー更新だけでは反映されません。再起動後にCtrl+F5で画面を更新し、ソリューションを読み込み直してください。モデルURLや新たなパス入力設定を増やしていません。チェック履歴の保存方式・外部エージェントから接続する方針・CI停止はそのままです。

実施した検証: Node.js **153件成功**（追加13件）、Chromiumで新UIの5画面幅 **114項目成功**、既存のプロジェクト調査フローの4画面幅 **32項目成功**。APIは模擬応答で、実際の新HTML/JS/共通CSSを使用しています。従来のstyles.css/app.jsはこの分離DOM検証では省略しています。本物のASP.NETやMCP経由の成功とは主張しません。

C#に複数プロジェクトの同名型の分離、プロジェクト間参照、参照グラフの方向に関する3テストを追加しました。ただしこの環境には.NET SDKがなく、ダウンロード先の名前解決も失敗したため、**C#ビルド・C#テスト・Windows実機・実ソリューションの読み込みは未実施**です。上記のNode/ChromiumテストにC#検証は含みません。
