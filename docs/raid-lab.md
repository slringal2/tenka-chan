# RaidLab: 6プロジェクトの実践用サンプル

今回の追加は外部OSSではなく、新しく作った戦闘ログ集計の教材です。GameLabは削除・変更していません。Domain / Infrastructure / Application / Host / Tests / Benchmarksの6プロジェクトを .sln と .slnx にまとめています。

## 使い始める手順

本体と外部MCPアダプターを終了し、`git pull --ff-only`。その後、本体ルートの **run-raid-lab.bat → 1 → Y** でサンプルの初回準備を行います。6プロジェクトのNuGet復元、本体4プロジェクトのReleaseビルド、仕様テストを順に実行します。DLLパス等の手入力は不要です。失敗時は止まり、画面とartifacts/logsのログを残します。

通常の `start.bat` で甜花ちゃんを起動し、**プロジェクト調査 → 準備 → 付属サンプル → RaidLab（実践・6プロジェクト） → 選んだサンプルを使う → 読み込む**。起動・ビルドの対象は **Tenka.Sample.RaidLab.Host** です。追加のサイドバーメニューは作っていません。

静的解析は6プロジェクト全体を対象とします。テストとベンチマークを実際に実行するのは別操作です。必要な場合のみ「実行・検証」のプロジェクト一覧から選びます。HostのビルドのみではTests/Benchmarksの実行は行いません。

## 機能と調査の入口

JSON読込 → 入力検査 → 重複イベント除外 → スキル照合 → プレイヤー別集計 → ギルド別集計 → 順位付け → レポートという一連の処理を、プロジェクトをまたいで追えます。

- **BaselineRaidAnalyzer.Analyze**: 繰り返しのToList/ToArray、線形重複検索、再集計を含む基準実装。
- **IndexedRaidAnalyzer.Analyze**: Dictionary/HashSetと一回走査を使う改善候補。毎回の索引作成費用も測定に含む。
- **RaidReportService.GenerateAsync**: JSON処理も含めた非同期のパイプライン。
- **RaidBatchService.GenerateAsync**: 並列数を最大4に制限した複数レポート生成。
- **ReportFormatter**: string +=とStringBuilderを比較。
- **LegacyEndpointExamples.BlockingAsync**: 非同期メソッド内のResult/Thread.Sleepを調べる静的解析専用コード。実行入口からは呼ばない。

本体は外部NuGetパッケージ不要の.NET 8、Testsは既存と同じxUnit、Benchmarksは既存と同じBenchmarkDotNetバージョンを使用します。外部ファイル、DB、ネットワークに依存するゲームサーバーではなく、メモリ上に生成したデータを処理します。ビルド・パッケージ復元・計測ツールによるファイル/通信は別です。

データの規模はSmall=20人/500イベント、Normal=200人/6000イベント、Large=800人/20000イベント。負荷の上限、起動引数の検査、90秒の協調的中止制限を用意しています。ゲームエンジン、GUI、自動インストール、Docker、CIは不要です。

## 検証と計測

**56ケースの仕様テストを作成**しています。正解を手計算した固定例、重複の先勝ち、不正参照、同点順序、上位切り出し後のギルド合計、整数上限、キャンセル、JSON異常、差分比較27条件等です。Hostの`--verify`とxUnitで同じテスト実装を使います。期待値はサンプル内のCONTRACT.mdで説明しています。

BATは1=初回準備、2=仕様テスト、3=参考比較、4/5=各版の4秒実行、6=xUnit、7=集計単体のBenchmarkDotNet、8=パイプライン全体のBenchmarkDotNet、9=ソリューションの場所、0=終了。4/5はアプリを動かすだけでトレース採取ではありません。

甜花ちゃんの起動プリセットにはベースライン／改善候補／4並列バッチを追加しました。プロファイル取得時に選択します。固定時間方式は処理回数が違うため総割り当て量を1回あたりの改善率にしません。JITは同期のAnalyzeメソッドから試します。通常起動は両版を呼ぶので、対象フィルターを選んで取得できます。

外部エージェントは `tenka_sample(sample="raid-lab")` を呼ぶと、ソリューションとHostのパスを取得できます。既定の `tenka_sample()` はGameLabのままです。新しいMCPツール名やモデル接続設定は追加していません。
