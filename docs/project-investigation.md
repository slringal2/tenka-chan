# プロジェクトを一度選び、ボタンで調べる

## 普段使う入口

サイドバーの **プロジェクト調査**、またはダッシュボードの **クラスを選んで調べる** を開きます。既に同じサーバーで読み込んだプロジェクトがあれば、その状態を引き継ぎます。新規なら最初の「参照…」で `.sln` / `.slnx` / `.csproj` を選び、読み込みます。単に画面を開いたり対象を選んだりしても、ビルド・対象アプリ・テスト・AIを自動実行しません。

**プロジェクト選択 → Releaseビルド＋解析 → クラス選択 → メソッド選択 → 調査ボタン** が基本操作です。通常の調査では追加のDLL/PDB/ソース/保存先パス、メソッドID、結果IDを入力しません。候補が複数ある場合は一覧を選びます。別のプロジェクトを手入力中のパスを自動で上書きしません。

## この画面のボタンで行えること

| 操作 | 自動的に引き継ぐ情報 | 表示するもの |
|---|---|---|
| Releaseビルド＋解析 / 静的解析だけ | 読み込み済みプロジェクト | ダッシュボードと共有する静的結果、次の操作 |
| クラス・型を選ぶ | Roslynの型シンボルとソース | 基底型、インターフェース、フィールド/プロパティ、partial宣言、メソッド一覧、解析済み指摘 |
| クラス / メソッドの参照を探す | 型/メソッドの識別子 | ソリューション内の参照。呼び出し元メソッドが索引にある場合はボタンで移動 |
| メソッドを選ぶ | 選択クラスのメソッド | ソース、直接の呼び出し元/呼び出し先、制御フロー、読み書き、コンパイル診断 |
| IL・PDBを調べる | 検出DLL、隣接PDB、索引のC#パス | IL命令、PDBの確認状態。候補が1つなら表示、オーバーロードが複数なら署名を選択 |
| JIT機械語を取得 | 選択メソッドのフィルターと実行アプリ | 保存結果、取得メソッド一覧、命令/分岐の再解析と比較元の選択 |
| プロファイル＋詳細イベントを取得 | 実行DLLと自動保存先 | 観測スレッドを選んでホットスポットへ反映、GC/割り当て/ロック競合を解析 |
| 境界値テスト案を見る | 引数型 | 入力候補と不足する条件。期待値/正しさは捏造しない |
| 既存テスト / ベンチマークを実行 | 検出したプロジェクトと自動保存先 | TRXの成功/失敗件数、BenchmarkDotNetの時間/割り当て、実行ログ |

実行可能なアプリが1つなら自動選択します。クラスライブラリの場合は呼び出し元アプリを候補から選びます。DLLがない場合はビルド、計測ツールがない場合はsetup.bat、対応できないJITメソッドは理由を表示します。実行条件は通常折りたたみ、必要なアプリだけ起動引数を指定します。GameLabには4秒観測のプリセットがあります。

共通サイドバー/テーマを使い、クラス一覧と詳細を横並びにしました。狭い画面は縦並びです。選択中の対象、次の操作、無効ボタンの理由、進行中/キャンセル/失敗を区別します。調査結果は構造化して表示し、内部のパスやJSONは確認用の折りたたみに分けています。

## 安全性・適用範囲

- 新APIは現在のスナップショットと不透明な選択IDを受け取り、サーバーが対象パスを解決します。任意のパスやコマンドを受け取りません。古いスナップショット、存在しない選択、別プロジェクトのIL対応は拒否します。操作全体を既存のワークスペースゲートで直列化し、二重実行はキューに入れません。
- 既存のループバック/Origin/CSRF/許可ディレクトリの制約を維持します。ボタンは制約を迂回しません。MSBuild/対象アプリ/テスト/ベンチマークは隔離なしのローカル実行で、各実行の承認が必要です。DockerもGitHub CIも使用しません。
- 型索引は宣言シンボルに基づき、メソッドのない型、partial、入れ子、同名別名前空間を区別します。最大20,000型、検索200文字、一覧はページング、詳細は宣言16個/80,000文字/メンバー500/メソッド1,000まで。暗黙の生成型やトップレベル文は型一覧の対象外です。
- ILの初期候補はメタデータ型名/メソッド名による照合です。同じソースビルドの証明ではありません。候補のSHA-256を再確認してトークンの取り違えを防ぎます。PDBの検査は既存の仕組みを使用し、PDBに書かれた任意パスは辿りません。
- JITはアプリを通常起動します。選択メソッドだけを任意の引数で呼び出す機能ではありません。起動後にそのメソッドが呼ばれる必要があります。ジェネリック/抽象/externなど自動取得できない対象は理由を表示します。同名オーバーロードが複数出力される場合は取得後に署名を選びます。
- テスト/ベンチマークの検出範囲は読み込み済み.csprojと各プロジェクト直下のTests/Benchmarksです。XML内の既知のパッケージ/IsTestProjectを確認します。任意のMSBuildインポートに依存する種別は完全には解決しません。独自の配置は最初にテストを含むソリューションを選ぶと利用できます。
- 既存のテストを実行する機能と、境界値入力の提案は別です。任意クラスの有効なインスタンス、DI設定、期待値を自動生成するものではありません。AIレビューや生成実験の既存画面は引き続き残します。
- 自動保存先は対象プロジェクト配下の `.tenka/profiles` / `.tenka/tests` / `.tenka/benchmarks`。許可された通常ディレクトリだけに作成します。対象のGit設定は勝手に変更しません。外部プロジェクトでは必要に応じて `.tenka/` を無視設定に追加してください。本リポジトリは追加済みです。
- 実行結果一覧は現在のWebサーバー内の直近20件で、同じソーススナップショットのみ表示します。サーバー再起動/ソース再読み込み後の履歴の再関連付けは未対応です。JIT/traceの元ファイル保存は既存の仕組みです。
- テスト/ベンチマークのビルドは参照DLLを変更する可能性があるため、古い解析を無効化してソースを再読み込みします。再読み込みできない場合、成功した実行結果と未完了の解析を区別します。過去のJITと新ビルドの同一性は主張しません。
- 通信/出力読取の失敗時に処理を自動再実行しません。中止は子プロセス終了の保証やサンドボックスではありません。--no-restoreも対象コードやBenchmarkDotNetの内部通信を遮断しません。短いベンチマークは予備測定です。

## 更新

今回はC#も更新します。起動中の甜花ちゃんの黒いウィンドウでEnterを押して終了し、本体フォルダーで `git pull --ff-only`、その後 `start.bat` を実行します。依存関係の復元が必要と案内された場合のみsetup.batを使います。ブラウザーはCtrl+F5で更新します。通常は「プロジェクト調査」を入口にしてください。

## この変更で実施した検証

Node.jsの新規33テストに既存のシェル/ダッシュボード/パス選択テストを合わせ、**100テストが成功**しました。読取のみの初期化、承認拒否、二重実行、ID以外のパス/コマンド混入の除外、古いスナップショット、曖昧な候補、引数検査、失敗表示、HTML配線を確認しました。

Chromiumでは実際の新HTML/共通シェル/クライアント/UIコードを用い、1440/768/390/320幅で**32確認項目**を通しました。APIは模擬応答、従来のstyles.cssはこの分離DOM検証では省略しています。管理ポリシーによりHTTPページ遷移が利用できず、set_contentとfetchバインディングを使用しました。これはASP.NET、実際の計測、Windowsダイアログ、完全なブラウザーE2Eの検証ではありません。

JavaScript/Pythonの構文、差分の空白、C#ファイルの変更範囲も確認しました。C#の追加15ケース（AdhocWorkspace索引/参照/出力先ガード）は実装しましたが、**.NET SDKとPowerShellがないためC#ビルド/テスト/Windows実行は未実施**です。ダウンロードも利用できませんでした。テスト定義を成功扱いにはしていません。CIを再開しての検証も行っていません。
